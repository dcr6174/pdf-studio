# PDF Studio implementation rules

- Stack: React 19 + TypeScript, Next-compatible routing through Vite + vinext (`vite.public.config.ts`), deployed to Cloudflare Workers with optional D1 owner analytics. It is not a static export; do not add Next-only APIs vinext does not shim.
- `app/page.tsx` is the Studio monolith and is risky to edit. Prefer standalone components/routes; file intake goes through `lib/file-handoff.ts` + `components/handoff-injector.tsx` (putHandoff -> navigate -> drop into the first PDF input). Why: small monolith edits have repeatedly broken unrelated tools.
- The tool catalogue lives in `lib/tools.ts`; public routes in `lib/seo-tools.ts`; the "100+ tools" count is always `PDF_TOOL_COUNT`, never a hardcoded number. Image Studio and Lab collections are separate. Why: hardcoded counts drift from the registry and ship lies in marketing copy.
- Document processing is on-device (pdf-lib, PDF.js, PDFium WASM, vendored Tesseract cores in `public/vendor/ocr`). Never upload document bytes, filenames or text to the server; analytics events exclude them by schema. Why: the privacy promise is the product.
- Brand assets live in `public/brand/` under versioned names (`*-v10.png`, `*-v11.svg`). Never overwrite a published brand file in place: Cloudflare caches `/brand/*` for 7 days, so changed bytes need a new filename and updated references. The wordmark text inside `pdf-studio-lockup-*-v6.svg` is owner-approved; keep its paths byte-identical.
- Build regenerates `public/social/*`, `public/test-fixtures/*`, `public/brand/options/*` and `scripts/site-assets-state.json`. Do not commit that drift; commit only intentional source changes. `npm run build` runs `tsc --noEmit` plus `checks/` verifiers first - a green build is the bar before any PR.
- Deploys: merging to `main` triggers Cloudflare Workers Builds (auto build + deploy). Manual deploy needs the D1 id via `scripts/configure-public.mjs` and Cloudflare API credentials in env; never commit either. Always work on a branch + PR, never push to local `main` directly.
- The Android app "PDF Studio A" is a Capacitor shell whose `server.url` points at the live site, so site deploys update the app. Native bridges (save-to-Downloads, open-with) live in `lib/app-bridge.ts`; `isNativeApp()` must stay a safe no-op in browsers. AdSense (`components/site-ad.tsx`) is skipped inside the app - AdSense is web inventory; apps fall under AdMob rules.
- The offline service worker (`public/sw.js`) registers only on the production host. Test offline behavior against the live site, not localhost.
- Generated download names keep `pdf-studio` branding, including ZIPs. My files (the shelf) is browser-local IndexedDB only: no uploads, no hosted links - keep the privacy wording accurate.
