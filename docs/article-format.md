# Approved PDF Studio article format

User approved the Alternate & Mix direction on 7 October 2026.

1. Clear how-to title and tool CTA at the top. Action pages remain free of article content.
2. Exact visible button names and input-order steps. Explain correction paths, not vague advice.
3. Practical worked example and real test evidence before optional Buddy story. Worked example navigation targets the actual tested block.
4. Tests show the date and browser, and distinguish a fresh processing run from inspection of a published sample. Do not invent test results, screenshots or browser versions. Record limits explicitly.
5. Refresh real screenshots when names change. Keep the automation pointer outside capture bounds. Result captures focus on completion and download; do not include the preview area. Offer actual output separately for inspection.
6. Buddy demonstrates each tool’s real action with labelled inputs and output. Put the main animation above supporting scenes; retain independent Buddy story Play/Pause/Replay and reduced-motion support. Do not reuse the interleave sequence for unrelated tools.
7. Include task-specific troubleshooting, meaningful FAQs, a CTA after the story and another after FAQs.
8. Responsive spacing, readable controls, keyboard navigation and real-device testing before claiming phone verification.

Apply these standards to remaining article drafts. This approval sets the format; it does not supply missing processing evidence or justify publishing unverified content.

## Sample download policy

Every blog and guide should offer tool-specific verified input downloads beside its worked example, using ArticleSamples. For multi-input tools provide separately downloadable source files (PDF A and PDF B here), plus an optional verified output link. Use only samples actually tested with that tool. Never render this component, sample-download panels or blog copy on the main action pages. This is the approved policy for all future articles and guides.

## Interactive learning and CTA refinement

Place a large centered tool CTA immediately below verified samples, after Buddy and after FAQs, with generous spacing. Keep the automatic looping page-operation illustration independent from the user-controlled Buddy story. The operation illustration loops without a visible pause button as requested; stop while the page is hidden and respect reduced motion. Keep user controls on the separate Buddy story.

Optional article/guide practice workspaces may teach the tool with sample cards. Clearly identify them as practice; never imply that a puzzle is real PDF processing. Support drag-and-drop, tap and keyboard reordering, validate the exact target sequence, and celebrate only a correct result. Keep celebratory motion brief and disable it for reduced motion. Do not add these learning panels to action pages.

## Header Buddy interaction

Article/guide hero Buddy loops automatically and silently, with no tap prompt or playback controls, independently from the larger operation illustration and practice puzzle. Use vector rendering to stay sharp at 4K and show a static final sequence in reduced-motion mode. Keep the main tool CTA ahead of Buddy on phone layouts. Variants for different tools/articles must depict their actual operation, not reuse an unrelated interleave example.

Use readable source labels (A/B) and page-specific output labels (A1/B1…). Give worked examples, verification notes and sample downloads generous vertical spacing. Diagram headings and arrows must remain readable in dark mode.

Public site pages must not link to the PDF Studio GitHub repository or expose commit identifiers. Keep source references and implementation verification in repository documentation only.

## Mandatory tool-blog hero and reading rhythm — 8 October 2026

Every new tool blog must have an operation-specific hero animation, not just a bouncing mascot. Reuse the logo-style Buddy and show the actual tool transformation using readable input/output labels. Merge shows all A pages followed by all B pages; Alternate & Mix shows alternating sources. Tailor labels and troubleshooting copy to each article. Never substitute an unrelated tool animation.

The hero plays automatically without tap prompts, loops smoothly and silently, pauses when its tab is hidden, and uses a static meaningful final state for reduced motion. Prefer responsive SVG/code-native vector artwork so it stays sharp at 4K; do not describe a small raster as 4K. Keep the top tool CTA before the illustration in phone reading order. The separate explanatory story retains Play/Pause/Replay. A decorative illustration is never test evidence.

Use generous editorial spacing: approximately 18–20px between paragraphs, 36–48px between sections, 14–16px between nearby controls and 28–40px around tool CTAs. Keep text to a comfortable reading width with line-height around 1.75–1.8. On phones preserve about 20px side gutters and allow labels to wrap. Avoid tightly packed form-like blog layouts.

Before publishing: check the hero describes this tool, inspect desktop and phone layouts, verify paragraph/button separation and reduced-motion behaviour, confirm the worked-example evidence remains honest, and check samples and CTA links. Include these checks in each three-article release.
