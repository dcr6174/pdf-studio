## Validation and delivery

Run `npm run lint`, `npx tsc --noEmit`, `npm run build:public` and the regression checks listed in README. `checks/verify-audit-fixes.mjs` exercises the new output paths using real PDFs, PDF.js rendering with a native test canvas, reopening via pdf-lib, and independent Poppler extraction. It is not a browser or real-device test.

The local Vite server starts on 127.0.0.1, but the available browser rejects localhost with `ERR_BLOCKED_BY_CLIENT`. Therefore screenshots, mobile keyboard, Nord 2 touch/camera, hover, scroll/focus and installed-PWA behavior are **unverified**. No live usability score or performance score is claimed.

A successful local build is not a deployment. Cloudflare deployment credentials and the production D1 binding are unavailable in this environment; no deployment or cache purge is claimed. Use the production configuration and existing Cloudflare deployment pipeline, then check CSS/JS asset responses and repeat phone/desktop upload-to-download tests.

## Follow-up implementation: remaining practical gaps

This follow-up implements the previously deferred file-card drag handles/previews, grouped range splitting, custom/selected-page resize with Fit/Fill, best-effort compression targeting, per-step workflow settings, and a responsive page-options drawer. README documents the exact semantics and remaining constraints.

- Merge previews and counts use retained pages. Explicit Move up/down remains available for touch and keyboard; hardware drag behavior is unverified.
- Group split exports are reopened and their page-text order independently checked with Poppler. Names and page allocations are available before export.
- Custom selected-page Fill output is independently rasterized and checked for source content. Unselected page dimensions are unchanged. Fill clipping is not redaction. The fit diagram is illustrative geometry, not a live document render.
- Compression targeting keeps the smallest candidate and distinguishes target reached/not reached. Tests cover impossible goals, invalid goals and byte identity when already within target. A universal compression-quality corpus is still missing.
- Workflow settings are allowlisted, follow step reorder/duplicate/disable, and survive safe recipe import/export. Failure identifies the step; intermediate recovery and per-file workflow outcomes remain outstanding.
- Page options now use a Radix sheet: right side on desktop, bottom on mobile, with a scrollable fieldset and 44px controls. Focus/touch/viewport checks remain unverified.

Deployment prerequisite check: GitHub main includes the Lab, blog and shared-footer commits; no open PRs were found. Wrangler is unauthenticated in this workspace and the local D1 binding contains a placeholder. Therefore no production deployment or cache purge is claimed. Do not use the placeholder configuration to deploy over the working production service.

Remaining larger work: faithful Office conversion and multi-sheet inference, multilingual searchable OCR/deskew with Unicode shaping, existing-document form-field design, automatic differences, per-file workflow progress/checkpoints, a true fit preview and representative conversion/compression fixtures. These require independent export validation, not catalogue labels. All existing validation limits remain visible only after rejected input; no limits table is reintroduced.

Workflow per-file mode is now exposed through the existing batch runner, with a local `results.csv` outcome ledger and `failures.txt` for failures. CSV formula injection is neutralized. This closes the missing per-file outcome UI wiring; per-step checkpoints and full browser batch acceptance remain unverified.
